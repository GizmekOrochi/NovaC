# NovaC

NovaC is a framework for building programming languages.

Unlike traditional compiler frameworks that impose a fixed architecture, NovaC aims to provide reusable infrastructure while allowing each language to define its own syntax, semantics, runtime model, compilation pipeline, and backend architecture.

## Philosophy

NovaC is not a language.

NovaC is not a compiler.

NovaC is a language-construction framework.

The framework should know as little as possible about the language being built.

A language defines:

* Tokens
* AST nodes
* Parsing rules
* Type system rules
* Traits
* Templates
* Macros
* Runtime semantics
* Lowering stages
* Backends
* Compilation pipeline

The framework only provides infrastructure.

## Core Components

### Lexer

The lexer is fully registry-driven.

Languages register:

* Keywords
* Symbols

Example:

```cpp
language.lexer.keyword("if");
language.lexer.symbol("+");
language.lexer.symbol("==");
```

---

### AST

AST nodes are declared at runtime.

Example:

```cpp
language.nodes.registerNode({
    "binary",
    {
        {"left", ast::FieldKind::Node},
        {"right", ast::FieldKind::Node},
        {"op", ast::FieldKind::String}
    }
});
```

---

### Parser

The parser is domain-based.

A language can define arbitrary parse domains:

```txt
expression
statement
declaration
type
pattern
module
```

Example:

```cpp
language.parser.prefix(
    "expr",
    "$int",
    parseInteger);
```

---

### Runtime

The runtime knows nothing about functions, variables, blocks, programs, or statements.

Everything is language-defined through handlers.

Example:

```cpp
language.runtime.expression(
    "integer",
    integerEvaluator);
```

---

### Lowering

NovaC provides generic lowering registries.

Languages may define:

```txt
AST -> HIR
HIR -> MIR
AST -> Bytecode
AST -> AST
```

The framework does not require a specific lowering strategy.

---

### Compiler Passes

Compilation is pass-based.

Example:

```cpp
compiler.addPass<ParsePass>("ast");
compiler.addPass<AstValidationPass>("ast");
compiler.addPass<HIRLoweringPass>("ast", "hir");
compiler.addPass<MIRLoweringPass>("hir", "mir");
```

The language chooses its own pipeline.

---

### Artifacts

Passes communicate through artifacts stored in the compilation context.

Example:

```cpp
context.setArtifact("ast", ast);
context.setArtifact("hir", hir);
context.setArtifact("result", value);
```

Artifacts may contain any data type.

---

### Backends

Backends are fully pluggable.

Example:

```cpp
language.backends.add(
    "llvm",
    [] {
        return std::make_unique<LLVMBackend>();
    });
```

## Design Goals

* Language-agnostic
* Extensible
* Runtime configurable
* Pass-driven
* Registry-driven
* No hardcoded language semantics
* Minimal framework assumptions

## Current Status

NovaC currently provides:

* Lexer
* AST registry
* Parser domains
* Runtime registry
* Lowering registry
* Pass system
* Backend registry
* Traits
* Templates
* Macros
* Modules

The project is currently focused on architecture and framework design.
